# blog-stat-collector

내 네이버 블로그 통계(유입경로, 검색어, 조회수·방문자·시간대·성별연령 등 28종)를 매일 모아 쌓고, 한 화면에서 보는 도구.
네이버 블로그 통계에는 공개 API가 없어서, 통계 화면이 내부적으로 부르는 JSON API를 로그인된 내 세션으로 직접 호출한다.

| 버전 | 위치 | 상태 |
|---|---|---|
| **v2 크롬 확장** | [`extension/`](extension/README.md) | 현재 버전. 수집·저장·대시보드가 모두 내 크롬 안에서 돈다. 서버도 DB 서버도 없다 |
| v1 Java | `src/` (태그 `v1.0.0`) | 보존. 확장 이식의 골든 데이터 생성기와 비교 기준으로 남겨 둔다 |

## v2 크롬 확장

TypeScript · Chrome MV3 (offscreen document) · SQLite WASM (OPFS) · Highcharts · three.js · node:test

```
 크롬에 네이버 로그인돼 있음 (쿠키는 브라우저가 붙인다. 확장은 값을 읽지 않는다)
        │
 [background]  설치·시작·30분 알람·팝업 "지금 수집" ─▶ 오프스크린 문서를 띄운다
        │
 [offscreen]   수집 회차: 로그인 확인 → 빠진 것만 계획 → 허용 목록 GET (요청 사이 1~2초)
        │                                              │
        ▼                                              ▼
 [db.worker]  SQLite (OPFS) ◀── 저장 ──  유입경로·검색어·상세 URL·지표 28종
        ▲
        │ chrome.runtime 메시지 (fetch('/api/dashboard/...')를 가로채 로컬 조회로)
 [dashboard]  개요 / 유입분석 / 블로그 지표 / 검색어 변화 / 검색어  (SPA, #/referer 등)
```

### 설치

1. `cd extension && npm install && npm run build`
2. 크롬 `chrome://extensions` → 개발자 모드 → "압축해제된 확장 프로그램을 로드" → `extension/dist`
3. 코드를 바꾼 뒤에는 `npm run build` 후 확장 카드의 새로고침(↻). **확장을 삭제하면 데이터도 지워지므로** 다시 설치하지 말고 새로고침한다(삭제가 필요하면 옵션에서 백업 먼저).

### 화면

- **개요**: 유입경로 합계, 검색 비율, 일별 추이, 유입처 순위
- **유입분석**: 모든 유입처의 상세(검색어·URL)를 클릭 없이 펼쳐 잘리지 않은 전문으로 본다. URL은 사람이 읽는 라벨로 풀이한다(이웃 새글 피드, 다른 블로그 글, 플레이스 검색어 등). `유입처별 | 블로그별` 전환, 찾기, CSV
- **블로그 지표**: 조회수·방문·순방문자·사용시간·이웃 증감·성별연령·기기·국가·인기 글·게시글별 추이·서비스 평균 비교, 그리고 요일×시간 **3D 지형도**(독자가 오는 시간)
- **검색어 변화 / 검색어**: 지난주 대비 새로 뜬·늘어난·줄어든 검색어, 전체 검색어 표
- **팝업**: 마지막 수집 결과, 오늘 요청 수, "지금 수집"(빠진 것 채우기 + 어제 다시 받아 덮어쓰기)
- **옵션**: 백업·복원(.sqlite), Java v1 데이터 가져오기, 하루 요청 상한, 최근 7일 다시 받기

자세한 동작·권한·데이터 소스는 [extension/README.md](extension/README.md)에 있다.

## 설계 결정과 이유

**DOM 대신 내부 JSON API.** 탐색 모드로 화면이 부르는 XHR을 모두 기록해 API 29종을 찾았고, 지표로 쓸 수 있는 것을 골라 수집한다(평가 표는 [CLAUDE.md](CLAUDE.md)). 화면 구조가 바뀌어도 덜 깨진다.

**응답을 믿지 않고 검증한다.** 응답 `rows`는 행이 아닌 컬럼별 배열이다. 유입처 방문수 합이 `refererTotalCount`와 같은지 확인하고, 상세(검색어·URL) 합이 유입처 방문수와 다르면 일부만 받은 것으로 보고 화면에 표시한다. 네이버 데이터 자체의 불일치(성별연령 구분 합 < 전체, 유입경로 합 < 조회수)는 원본 응답으로 확인해 기록했다.

**서버를 두지 않는다(v2).** 수집·저장·조회를 사용자 브라우저 안에서 끝낸다. 운영비가 없고, 데이터가 브라우저 밖으로 나가지 않으며, 로그인은 사용자가 평소처럼 크롬에서 한 상태를 그대로 쓴다. 쿠키 값을 읽거나 저장하지 않는다.

**DB는 한 곳만 연다.** OPFS 동기 핸들은 독점이라, SQLite는 오프스크린 문서의 워커 하나만 연다. 대시보드·팝업·옵션은 메시지로 질의한다. 스키마는 `schema_version`으로 마이그레이션한다.

**이식은 골든 테스트로.** Java 파서·수집 계획에 같은 픽스처를 넣어 결과를 JSON으로 덤프하고, TS 테스트가 행 단위로 똑같은지 확인했다. 그동안 찾은 함정(`hour=05`는 두 자리, 삭제된 글의 400은 정보 지표에만 표시, 15일 창, 같은 API 지표 묶기)도 테스트로 고정했다.

**빠진 것만, 멱등하게.** `collection_state`와 저장된 행으로 빠진 (지표, 날짜)만 계획한다. 저장은 날짜 단위로 지우고 다시 넣어 몇 번 받아도 결과가 같다. 네이버가 늦게 집계하는 값(순방문자·시간대)은 0으로 오면 저장하지 않고 다음 확인 때 다시 받는다. 오늘 끝난 뒤에도 새 할 일이 생기면 다시 돌고, 같은 실패만 남았으면 그날은 쉰다(응답 형식이 바뀌었을 때 재요청 폭주 방지).

**재시도는 실패 종류별로.** 타임아웃·429·5xx는 지수 백오프 + 지터로 재시도하고 429는 `Retry-After`를 따른다. 401/403은 로그인 만료라 즉시 멈춘다. 요청은 허용 목록 경로의 GET만 보낸다.

**하지 않기로 한 것.** ID/PW 자동 입력, 캡차 우회, 다른 계정 수집. 처음 수집한 블로그에 묶여 다른 계정으로 로그인돼 있으면 받지 않는다. 원격 코드와 분석·원격 로그는 넣지 않는다(라이브러리는 모두 번들).

## v1 Java (보존)

Java 17 · Spring Boot 3.5 · Spring Data JPA · H2 · Playwright for Java · JUnit 5

수동 로그인한 쿠키를 파일로 저장해 Playwright로 API를 부르고, H2 파일 DB에 쌓는다. 대시보드는 쓰기 프로세스가 내보낸 스냅샷을 인메모리 H2에 올려 `127.0.0.1:8080`에서 읽는다(H2 `AUTO_SERVER`는 TCP 포트를 모든 인터페이스에 열어 쓰지 않았다).

| 하는 일 | 스크립트 (Windows) |
|---|---|
| 로그인 (수동, "로그인 상태 유지" 체크) | `scripts\login.cmd` |
| 매일 자동 수집 (상주) | `scripts\scheduler.cmd` |
| 검색어만 길게 수집 | `scripts\collect-queries.cmd [일수] [--force]` |
| 나머지 지표 전부 수집 | `scripts\collect-metrics.cmd [일수] [--force]` |
| 대시보드 http://127.0.0.1:8080 | `scripts\dashboard.cmd` |
| 확장으로 옮길 데이터 내보내기 | `./gradlew exportJson` → 확장 옵션의 "Java 데이터 가져오기" |

그 밖의 모드와 세부 규칙은 [CLAUDE.md](CLAUDE.md)에 있다.

## 개인 데이터

통계 데이터는 커밋하지 않는다. 확장은 데이터를 브라우저(OPFS) 안에만 두고, 백업 파일은 사용자가 직접 내려받는다. v1의 `.playwright-profile/`(로그인 쿠키), `data/`, `explore-output/`, 로그는 gitignore 대상이다.
