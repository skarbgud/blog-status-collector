# 블로그 통계 수집기 (크롬 확장)

네이버 블로그 통계를 **내 크롬 안에서** 수집·저장·조회한다. 서버도 DB 서버도 없다. 데이터는 이 브라우저 밖으로 나가지 않는다.
개인이 자기 PC에서 자기 블로그 하나를 보는 도구다(웹스토어 공개 배포는 범위 밖).

## 설치
1. `cd extension && npm install && npm run build`
2. 크롬 `chrome://extensions` → 개발자 모드 → "압축해제된 확장 프로그램을 로드" → `extension/dist`
3. 코드를 바꾼 뒤에는 `npm run build` 후 확장 카드의 새로고침 버튼

## 동작
- 크롬에서 네이버에 로그인돼 있으면 30분마다 확인해서 **어제까지 30일 중 빠진 것만** 받는다(브라우저 시작·설치 때도 확인).
- 요청을 하나도 보내지 않고 끝나는 경우: 로그인 쿠키 없음, 04:00 KST 전(네이버가 어제분을 늦게 확정), 오늘 끝났고 새 할 일이 없음, 하루 상한 소진(상한을 둔 경우), 최근 6시간 안 로그인 실패.
  - "새 할 일"은 로컬에서 센다(빠진 유입경로 날짜, 상세 URL만 빠진 날짜, 빠진 지표 단위). 오늘 끝난 뒤라도 확장을 새로 고쳐 수집 항목이 늘거나 데이터를 가져와 빈 곳이 생기면 다음 30분 확인에서 받는다. 지난 회차 뒤 남은 개수와 같으면(같은 실패만 남음) 그날은 다시 돌지 않는다. 네이버 응답 형식이 바뀌어 계속 실패할 때 30분마다 다시 요청하지 않게 하려는 것이다(`missing_after`).
- 요청 사이 1~2초(2026-11-21 2~5초에서 줄임), 401/403이면 즉시 중단, 429·5xx는 백오프 후 재시도. 하루 상한은 **기본 없음**(옵션에서 0 = 없음, 또는 50~100000회).
- 처음 수집한 블로그에 묶인다. 다른 계정으로 로그인돼 있으면 받지 않는다.
- 처음 30일치는 600~800회 안팎이고 상한이 없으면 한 회차에 받는다(1~2초 간격이라 약 15~25분). 상한을 두면 거기서 멈추고 다음 날 이어 받는다. 기존 Java 데이터를 가져오면 그만큼 줄어든다.
- **팝업 "지금 수집" = 빠진 것 채우기 + 어제 하루 다시 받아 덮어쓰기**(약 80회). 옵션의 "최근 7일 다시 받기"는 7일을 덮어쓴다. 이미 받은 날짜도 새로 받는다는 점만 자동과 다르고, 시각(04:00)·상한·간격은 똑같이 지킨다. 누르기 전에 예상 요청 수와 남은 상한을 보여 준다.
  - 덮어쓰기는 날짜 단위 교체다(그 날짜를 지우고 다시 넣음). 행 단위 upsert가 아닌 이유는 네이버가 다시 집계해 사라진 유입처·검색어 행이 남지 않게 하려는 것이다.
  - 다시 받을 때 네이버가 집계 전이라 빈 값(시간대 0 등)을 주면, 이미 저장된 확정값은 지우지 않는다(`MetricPlan.keepOnPending`).
  - 자동 회차가 도는 중에 누르면 시작하지 않고 "끝난 뒤 다시 누르세요"를 보여 준다(자동 회차에 묻혀 덮어쓰기 없이 끝나지 않게).

## 화면
- 팝업: 블로그(가림 처리), 마지막 확인 결과, 오늘 요청 수, 저장 범위, 진행 상황, "지금 수집", 대시보드·백업 열기
- 대시보드(`dashboard.html`): Java 대시보드의 지표를 옮겼다. 조회는 로컬 SQLite에서 한다(네트워크 요청 없음)
  - 왼쪽 메뉴는 **화면 전환(SPA)**이다(`static/dashboard-router.js`). `#/overview`, `#/referer`, `#/metrics`, `#/trends`, `#/queries` 중 한 화면만 보이고 뒤로가기·새로고침이 된다. 예전 앵커(`#referer-panel` 등)도 받아 준다. 데이터는 기간이 바뀔 때 모든 화면이 미리 불러 두고, 화면이 보일 때 그 안의 차트 크기를 다시 맞춘다(`reflow`).
- 유입분석(`#/referer`): 모든 유입처의 상세(검색 유입처는 검색어, 그 밖은 URL)를 처음부터 펼쳐 전문으로 보여 준다. 사이드바 기간으로 합산, 찾기·내 블로그 안 이동 숨기기·CSV.
  - 보기 전환 `유입처별 | 블로그별`: 블로그별은 `블로그 ○○` 배지가 붙은 줄(다른 블로그 글·글 목록·홈)과 `○○의 이웃 관리 화면`만 블로그 ID로 묶어 방문수 순으로 보여 준다. 줄마다 어느 유입처에서 왔는지 회색 칩으로 붙이고, 묶음마다 블로그 열기 링크가 있다. URL은 `core/referer-url.ts`가 라벨로 풀이한다(플레이스 검색어 디코딩 등). 상세 URL은 검색어와 같은 `/api/blog/daily/referer/total/detail`에 `searchEngine=0`을 보내 받는다(응답 `refererDetail`의 `referrerUrl`, `cv`, `cv_p`. `cv_p`는 그 유입처 안의 비율이다. URL은 잘리지 않은 원문으로 온다. 2026-11-20 화면 캡처로 확인했고, 상세 합이 유입처 방문수와 같았다). 새로 받는 날짜는 유입경로와 함께 받고, 유입경로만 있는 날짜(가져온 H2 데이터, 이 기능 전에 받은 날)는 저장된 유입처 목록으로 URL만 보충한다(`collection_state`의 `REFERER_URL`). 하루에 방문이 있는 검색 아닌 유입처 수만큼(약 5~8회) 요청이 늘고, 보충은 하루 상한 안에서 나눠 받는다. 한 유입처라도 실패하면 그 날은 받은 날로 남기지 않아 다음 회차에 다시 받는다. URL은 로그에 남기지 않는다.
- 옵션(`options.html`): 백업 받기(.sqlite), 백업에서 복원, Java 데이터 가져오기, 하루 요청 상한, 최근 7일 다시 받기

## 공유 링크
대시보드 사이드바 "공유 링크 만들기": 지금 기간의 화면 전부(검색어·유입 URL 포함)를 링크 하나에 담아 클립보드에 복사한다. 받은 사람은 확장·로그인 없이 브라우저로 읽기 전용으로 본다.
- **데이터는 어디에도 저장되지 않는다.** 데이터는 링크의 `#s=` 뒤(fragment)에 있고, 브라우저는 #뒤를 서버로 보내지 않는다. 보기 페이지(Netlify)는 화면 코드만 있는 정적 사이트다. 대신 **링크를 가진 사람은 누구나** 그 화면을 볼 수 있다.
- 만드는 쪽(`src/dashboard-share.ts`): 화면 스크립트가 받은 `/api/dashboard/*` 응답을 기록해 두었다가(fetch를 한 번 더 감쌈) 지금 기간 응답만 모은다. 수집 상태(`session`)는 뺀다. 화면이 아직 다 불러오지 않았거나 이전 기간 응답이 섞여 있으면 만들지 않는다.
- 데이터 형식(`src/core/share-codec.ts`): JSON → deflate-raw(브라우저 내장 `CompressionStream`) → base64url. 블로그 지표 응답은 열 형식으로 바꾸고, 화면이 쓰지 않는 지표(`REFERER_SEARCH`, `REFERER_SITE`, `RELATION_VISIT`)는 빼고, 소수는 셋째 자리까지 반올림한다. 풀 때 화면이 받는 모양으로 되돌린다. 풀었을 때 20MB를 넘으면 거부한다.
- 링크 길이(2026-11-21 실데이터): **7일 약 3.8만 자, 30일 약 11.8만 자.** 대부분이 게시글별 일 조회수·순위다. 크롬은 열 수 있지만 메신저에 따라 긴 링크가 잘릴 수 있어 3만 자를 넘으면 화면에 알린다. 길이 재기: `node tools/share-size.mjs <export.json>`(`npm test` 뒤).
- 보기 페이지(`src/share-viewer.ts`): `dashboard.html`에서 `dashboard-api.js`를 이것으로 바꾼 페이지다. 링크를 열면 데이터를 그 탭의 sessionStorage로 옮기고 주소를 `#/overview`로 바꾼다(화면 전환이 #를 쓰기 때문, 새로고침해도 유지). 기간 바꾸기와 확장 전용 표시(수집 상태, 백업 링크)는 숨긴다.
- 빌드·배포: `npm run build:viewer` → `viewer-dist/`(확장 빌드에서 화면 파일만 꺼내고, 화면이 import하는 `core/` 모듈만 따라가며 넣는다. 수집기·DB 코드는 올리지 않는다). Netlify는 저장소 루트의 `netlify.toml`로 빌드한다. 헤더: CSP `connect-src 'none'`(보기 페이지는 어디에도 요청하지 않는다), `Referrer-Policy: no-referrer`, `noindex`.
- 로컬 확인: `npm run build:viewer && node tools/serve-viewer.mjs` → http://localhost:8787/ (netlify.toml과 같은 헤더). 확장에서 "보기 페이지 주소 바꾸기"에 이 주소를 넣으면 공유 링크를 로컬에서 열어 볼 수 있다.
- 보기 페이지 주소는 처음 "공유 링크 만들기"를 누를 때 한 번 묻고 확장 페이지 localStorage에 둔다.

## 데이터
- 저장 위치: 확장의 OPFS(브라우저 내부) SQLite. **확장을 삭제하면 지워진다** → 가끔 옵션에서 백업을 받는다.
- 다른 PC로 옮기기: 백업 받기 → 새 PC에서 확장 설치 → 백업에서 복원
- 원문 응답은 파서를 고칠 때 다시 읽으려고 14일만 보관한다(로그인 확인 응답은 저장하지 않는다).

## 권한과 이유
| 권한 | 이유 |
|---|---|
| `https://blog.stat.naver.com/*` | 통계 API GET(허용 목록 경로만). 쿠키는 브라우저가 붙인다 |
| `cookies` | 로그인 쿠키(NID_AUT)가 **있는지만** 확인해 로그아웃 상태에서 요청을 0회로 만든다. 값은 쓰지·저장하지·출력하지 않는다 |
| `alarms` | 30분마다 확인 |
| `offscreen` | 수집 루프와 SQLite 워커를 서비스 워커 수명 제약 없이 실행 |
| `unlimitedStorage` | 브라우저가 공간 부족 때 데이터를 지우지 않게 |

원격 코드는 없다(sqlite-wasm, Highcharts 모두 번들). 분석 도구·원격 로그도 없다.

**차트 라이브러리 라이선스**: Highcharts는 상용 라이선스이고 **개인·비상업 용도에 한해 무료**다(www.highcharts.com/license). 이 확장을 상업적으로 쓰거나 배포하려면 라이선스를 사야 한다. 차트 아래 "Highcharts.com" 표시는 그대로 둔다.

## Java(v1)에서 옮기기
1. 이전 수집기 폴더에서 `./gradlew exportJson` → `data/export/blogstat-export.json`
   (스냅샷 `data/replica/snapshot.sql`을 인메모리 H2에 올려 내보낸다. 원본 DB 파일을 열지 않아 다른 프로세스와 충돌하지 않는다)
2. 옵션 → "기존 데이터 가져오기"에서 그 파일 선택. 확장에 이미 있는 날짜·지표는 덮지 않는다.

## 확인 도구(개인 데이터, 결과는 커밋하지 않는다)
- `npm test`: 파서·수집 계획(Java 골든), 저장소, 수집 회차, 조회 계층, 가져오기, 비교 도구
- `node build-test/tools/parity.js <export.json> [http://127.0.0.1:8080]`: 조회 계층이 Java 대시보드 API와 같은 응답을 내는지(2026-11-21: 23건 모두 일치)
- `node build-test/tools/compare.js <백업.sqlite> <export.json> [from] [to]`: 병행 운영 비교. 같은 날짜를 양쪽이 각자 받았을 때 행이 같은지(가져온 복사본은 제외)
  (도구는 `npm test`가 `build-test/`로 컴파일한 뒤 실행한다)

## 알려진 한계
- 로그인한 뒤 수집 시작까지 최대 30분(쿠키 변화 감지는 `.naver.com` 전체 권한이 필요해 쓰지 않는다). 바로 받으려면 팝업 "지금 수집".
- 네이버 응답 형식이 바뀌면 그 지표는 실패로 세고 건너뛴다(팝업에 실패 건수). 형식 변경을 따로 감지해 알리지는 않는다.
