# 블로그 통계 수집기 (크롬 확장)

네이버 블로그 통계를 **내 크롬 안에서** 수집·저장·조회한다. 서버도 DB 서버도 없다. 데이터는 이 브라우저 밖으로 나가지 않는다.
개인이 자기 PC에서 자기 블로그 하나를 보는 도구다(웹스토어 공개 배포는 범위 밖).

## 설치
1. `cd extension && npm install && npm run build`
2. 크롬 `chrome://extensions` → 개발자 모드 → "압축해제된 확장 프로그램을 로드" → `extension/dist`
3. 코드를 바꾼 뒤에는 `npm run build` 후 확장 카드의 새로고침 버튼

## 동작
- 크롬에서 네이버에 로그인돼 있으면 30분마다 확인해서 **어제까지 30일 중 빠진 것만** 받는다(브라우저 시작·설치 때도 확인).
- 요청을 하나도 보내지 않고 끝나는 경우: 로그인 쿠키 없음, 04:00 KST 전(네이버가 어제분을 늦게 확정), 오늘 이미 끝남, 하루 상한 소진, 최근 6시간 안 로그인 실패.
- 요청 사이 2~5초, 하루 상한 기본 300회(옵션에서 50~2000), 401/403이면 즉시 중단, 429·5xx는 백오프 후 재시도.
- 처음 수집한 블로그에 묶인다. 다른 계정으로 로그인돼 있으면 받지 않는다.
- 처음 30일치는 600회 안팎이라 하루 상한에서 멈추고 다음 날 이어 받는다. 기존 Java 데이터를 가져오면 그만큼 줄어든다.
- **팝업 "지금 수집" = 빠진 것 채우기 + 어제 하루 다시 받아 덮어쓰기**(약 80회). 옵션의 "최근 7일 다시 받기"는 7일을 덮어쓴다. 이미 받은 날짜도 새로 받는다는 점만 자동과 다르고, 시각(04:00)·상한·간격은 똑같이 지킨다. 누르기 전에 예상 요청 수와 남은 상한을 보여 준다.
  - 덮어쓰기는 날짜 단위 교체다(그 날짜를 지우고 다시 넣음). 행 단위 upsert가 아닌 이유는 네이버가 다시 집계해 사라진 유입처·검색어 행이 남지 않게 하려는 것이다.
  - 다시 받을 때 네이버가 집계 전이라 빈 값(시간대 0 등)을 주면, 이미 저장된 확정값은 지우지 않는다(`MetricPlan.keepOnPending`).
  - 자동 회차가 도는 중에 누르면 시작하지 않고 "끝난 뒤 다시 누르세요"를 보여 준다(자동 회차에 묻혀 덮어쓰기 없이 끝나지 않게).

## 화면
- 팝업: 블로그(가림 처리), 마지막 확인 결과, 오늘 요청 수, 저장 범위, 진행 상황, "지금 수집", 대시보드·백업 열기
- 대시보드(`dashboard.html`): Java 대시보드와 같은 화면. 조회는 로컬 SQLite에서 한다(네트워크 요청 없음)
- 유입분석(대시보드 `#referer-panel`): 모든 유입처의 상세(검색 유입처는 검색어, 그 밖은 URL)를 처음부터 펼쳐 전문으로 보여 준다. 사이드바 기간으로 합산, 찾기·내 블로그 안 이동 숨기기·CSV. URL은 `core/referer-url.ts`가 라벨로 풀이한다(플레이스 검색어 디코딩 등). 상세 URL은 검색어와 같은 `/api/blog/daily/referer/total/detail`에 `searchEngine=0`을 보내 받는다(응답 `refererDetail`의 `referrerUrl`, `cv`, `cv_p`. `cv_p`는 그 유입처 안의 비율이다. URL은 잘리지 않은 원문으로 온다. 2026-11-20 화면 캡처로 확인했고, 블로그_모바일 49 = 49처럼 상세 합이 유입처 방문수와 같았다). 새로 받는 날짜는 유입경로와 함께 받고, 유입경로만 있는 날짜(가져온 H2 데이터, 이 기능 전에 받은 날)는 저장된 유입처 목록으로 URL만 보충한다(`collection_state`의 `REFERER_URL`). 하루에 방문이 있는 검색 아닌 유입처 수만큼(약 5~8회) 요청이 늘고, 보충은 하루 상한 안에서 나눠 받는다. 한 유입처라도 실패하면 그 날은 받은 날로 남기지 않아 다음 회차에 다시 받는다. URL은 로그에 남기지 않는다.
- 옵션(`options.html`): 백업 받기(.sqlite), 백업에서 복원, Java 데이터 가져오기, 하루 요청 상한, 최근 7일 다시 받기

## 데이터
- 저장 위치: 확장의 OPFS(브라우저 내부) SQLite. **확장을 삭제하면 지워진다** → 가끔 옵션에서 백업을 받는다.
- 다른 PC로 옮기기: 백업 받기 → 새 PC에서 확장 설치 → 백업에서 복원
- 원문 응답은 파서를 고칠 때 다시 읽으려고 14일만 보관한다(로그인 확인 응답은 저장하지 않는다).

## 권한과 이유
| 권한 | 이유 |
|---|---|
| `https://blog.stat.naver.com/*` | 통계 API GET(허용 목록 경로만). 쿠키는 브라우저가 붙인다 |
| `cookies` | 로그인 쿠키(NID_AUT)가 **있는지만** 확인해 로그아웃 상태에서 요청을 0회로 만든다. 값은 쓰지·저장하지·출력하지 않는다 |
| `alarms` | 30분마다 확인 |
| `offscreen` | 수집 루프와 SQLite 워커를 서비스 워커 수명 제약 없이 실행 |
| `unlimitedStorage` | 브라우저가 공간 부족 때 데이터를 지우지 않게 |

원격 코드는 없다(sqlite-wasm, Highcharts 모두 번들). 분석 도구·원격 로그도 없다.

**차트 라이브러리 라이선스**: Highcharts는 상용 라이선스이고 **개인·비상업 용도에 한해 무료**다(www.highcharts.com/license). 이 확장을 상업적으로 쓰거나 배포하려면 라이선스를 사야 한다. 차트 아래 "Highcharts.com" 표시는 그대로 둔다.

## Java(v1)에서 옮기기
1. 이전 수집기 폴더에서 `./gradlew exportJson` → `data/export/blogstat-export.json`
   (스냅샷 `data/replica/snapshot.sql`을 인메모리 H2에 올려 내보낸다. 원본 DB 파일을 열지 않아 다른 프로세스와 충돌하지 않는다)
2. 옵션 → "기존 데이터 가져오기"에서 그 파일 선택. 확장에 이미 있는 날짜·지표는 덮지 않는다.

## 확인 도구(개인 데이터, 결과는 커밋하지 않는다)
- `npm test`: 파서·수집 계획(Java 골든), 저장소, 수집 회차, 조회 계층, 가져오기, 비교 도구
- `node build-test/tools/parity.js <export.json> [http://127.0.0.1:8080]`: 조회 계층이 Java 대시보드 API와 같은 응답을 내는지(2026-11-21: 23건 모두 일치)
- `node build-test/tools/compare.js <백업.sqlite> <export.json> [from] [to]`: 병행 운영 비교. 같은 날짜를 양쪽이 각자 받았을 때 행이 같은지(가져온 복사본은 제외)
  (도구는 `npm test`가 `build-test/`로 컴파일한 뒤 실행한다)

## 알려진 한계
- 로그인한 뒤 수집 시작까지 최대 30분(쿠키 변화 감지는 `.naver.com` 전체 권한이 필요해 쓰지 않는다). 바로 받으려면 팝업 "지금 수집".
- 네이버 응답 형식이 바뀌면 그 지표는 실패로 세고 건너뛴다(팝업에 실패 건수). 형식 변경을 따로 감지해 알리지는 않는다.
